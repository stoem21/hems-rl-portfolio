# GitHub Pages and the combined ngrok backend

Set the repository variable `VITE_BACKEND_URL` to the assigned HTTPS ngrok origin plus `/hems`.

```text
https://YOUR-ASSIGNED-DOMAIN.ngrok-free.app/hems
```

After source review and an authorized push, select GitHub Actions as the repository Pages source. Run **Deploy Pages (manual)** only when publication is intended. Its workflow is manual-only; a push does not trigger publication. The workflow sets Vite's base path using the project repository name and uploads `hems-backend/dist`, the configured frontend output directory.

For a local production build:

```bash
cd hems-frontend
VITE_BACKEND_URL=https://YOUR-ASSIGNED-DOMAIN.ngrok-free.app/hems VITE_SITE_BASE=/hems-rl-portfolio/ npm run build
```

The public URL is visible to visitors. Keep provider credentials and the ngrok authtoken solely on the backend host. The combined proxy must permit the website origin, e.g. `https://stoem21.github.io`.

The API helper adds ngrok's interstitial-bypass header for ngrok API bases. Existing AI streaming readers remain in use. Health checks run on entering Simulation or returning to a visible tab after the five-minute cache expires. There is no periodic polling; recent and in-flight checks are shared across component remounts. The Check connection button explicitly retries, and hidden tabs do not initiate health checks. A successful health response does not prove that data, checkpoints or models are loaded.

Before sharing, test health, a short rollout, agent comparison, streamed explanation and AI events against the live backend. Verify actual host resource usage and the ngrok plan's remaining request/data allowance. Verify `/hems/dashboard-data` returns the configured saved evaluation and that the UI shows its export timestamp. Stop the tunnel and reload: results must show an unavailable state instead of replacement values.

## Saved evaluation endpoint

Set `hemsDashboardDataFile` in the proxy's local `portfolio-ngrok.json` to an absolute path outside the public checkout. The current research host can use its existing generated `hems-frontend/src/data/dashboardData.js`. New exports generated by this repository go to ignored `private-results/dashboardData.js`; `.json` exports with the same fields are also supported. Use only a trusted local export because `.js`/`.mjs` files execute as modules. Restart the combined launcher after changing its configuration or proxy code.

`GET /hems/dashboard-data` returns `{schemaVersion: 1, data, source: {kind: "saved-evaluation", updatedAt, sha256}}`. It uses the proxy's existing CORS policy. Missing, incomplete or known fictional exports return HTTP 503. Results are requested once on page load, with a 20-second timeout and an explicit retry action. Refresh the page to load a changed export. Export file modification time is not the experiment execution time.

No FastAPI image rebuild is needed for this endpoint; the Node API proxy serves it. The inference service continues to handle simulations and AI calls.
